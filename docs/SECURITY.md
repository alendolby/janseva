# Security and privacy

Passwords use Argon2 through pwdlib. Registration creates only CITIZEN, regardless of extra client fields. Admin APIs alone create office/admin accounts. Password policy requires 12–128 characters with uppercase, lowercase and digits. JWTs carry subject, issuer, audience, expiry and session version. Backend loads the current user, checks activation and role every request. Logout/reset/permission change increments session version to revoke existing sessions. Single-use reset/verification tokens use SHA-256 digests and 20-minute expiry.

Bearer tokens live in React memory. No persistent browser token storage or refresh token is implemented. Reloading requires login. Requests use explicit Authorization headers, so ambient cross-site cookies do not authorize mutations. CORS permits only configured origins. Production requires HTTPS and a reviewed identity provider/session strategy.

Citizens query their own cases. Office scope includes assigned cases and configured escalation oversight. Escalation oversight is read-only unless reassigned. Admin resources require ADMIN. Evidence download/upload rechecks case access and evidence membership. Internal notes never appear in citizen timelines. Citizen identity fields are omitted from office complaint detail and map responses. System-wide user lists are admin-only.

Evidence accepts real JPEG/PNG content, verifies image integrity, limits pixels and re-encodes to strip metadata/trailing content. Passive PDF signatures/EOF are checked and embedded executable content indicators rejected. Extensions must match the detected content. Original client MIME labels are never trusted. Maximum file size is 10 MB. Generated storage keys contain no user filenames. Evidence downloads use attachment disposition and nosniff. This is not a full antivirus/CDR engine; malware scanning, object lifecycle cleanup and retention controls remain production requirements.

Rate limits use Redis in Compose and bounded in-process buckets for portable development. Auth routes permit 20 requests per IP/window; other APIs default to 120. Nginx uses an API proxy, so a production proxy deployment should review trusted-client IP forwarding and gateway rate limits. Multi-instance auth limits require the configured Redis backend. Logs contain method/status/timing without passwords, JWTs, email addresses or complaint descriptions.

Database integrity uses foreign keys, unique public IDs, coordinate/score/rating constraints and controlled status transitions. Atomic counter updates support concurrent case IDs. Row locks serialize case actions on PostgreSQL. Audit/event mutation triggers reject normal update/delete. Migration owners/superusers retain administrative authority, so operational backups and external tamper-evident logging should supplement these triggers in production.

Secrets are generated locally and excluded from the ZIP/Git. Use different secrets and a separate runtime database role for deployment. The demo creates no real citizen records, Aadhaar integration, government credential or external message recipient. SMTP is optional and not configured by default. Case-event notifications remain in-app in the MVP.
